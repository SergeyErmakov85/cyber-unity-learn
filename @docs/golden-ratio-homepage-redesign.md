# Перестройка главной страницы по золотому сечению

## Цель

Обновить главную страницу Neon Unity Neural так, чтобы визуальная иерархия, размеры блоков и расстояния опирались на золотое сечение `φ = 1,618`. Результат должен вести посетителя по ясному маршруту: ценность платформы → доказательство на реальном агенте → путь обучения → преимущества → действие.

Золотое сечение здесь — система пропорций, а не требование механически делить каждый элемент. Оно должно делать интерфейс спокойнее и понятнее, не ухудшая читаемость, доступность и адаптивность.

## Границы работы

- Изменяется только главная страница: [src/pages/Index.tsx](../src/pages/Index.tsx) и компоненты из [src/components/landing](../src/components/landing).
- Сохраняются действующие маршруты, CTA, интерактивные визуализации, данные `LEARNING_MAP`, хабы и SEO-разметка.
- Палитра остаётся семантической: `background`, `foreground`, `primary`, `secondary`, `accent`, `card`, `muted`. Не добавлять raw-hex и не заменять токены Tailwind-палитрой.
- Мобильная версия не использует двухколоночную схему: золотое сечение применяется к вертикальному ритму и размерам, а не создаёт узкую боковую колонку.

## Математика и базовые токены

### Основная пропорция

Для двух соседних зон используем отношение `1,618 : 1`:

```text
large = total / 1,618       → 61,8 %
small = total - large       → 38,2 %
```

При внутренних отступах `gap` сначала вычитается `gap`, затем оставшаяся ширина делится в отношении `1,618 : 1`.

| Ширина рабочей области | Большая зона (61,8 %) | Малая зона (38,2 %) |
| --- | ---: | ---: |
| 960 px | 593 px | 367 px |
| 1200 px | 742 px | 458 px |
| 1400 px | 865 px | 535 px |

В CSS/Grid предпочтительнее выражать это без ручных пикселей:

```css
grid-template-columns: minmax(0, 1.618fr) minmax(0, 1fr);
```

### Шкала интервалов

Ввести в `src/index.css` локальные utility-классы или CSS-переменные для главной страницы. Базовая единица — `8 px`; ряд близок к последовательности Фибоначчи и дружит с текущей 4/8-px сеткой:

| Токен | Значение | Применение |
| --- | ---: | --- |
| `--space-1` | 8 px | промежуток между иконкой и подписью |
| `--space-2` | 13 px | плотные группы в карточке |
| `--space-3` | 21 px | обычный внутренний отступ |
| `--space-4` | 34 px | расстояние между смысловыми группами |
| `--space-5` | 55 px | отступ под заголовком секции |
| `--space-6` | 89 px | вертикальный ритм большой секции |

Не нужно одновременно применять `py-20`, `mb-16`, `pt-12` по привычке: у каждой секции должен быть один явный внешний вертикальный отступ, кратный этой шкале.

### Типографика

Базовый текст остаётся `16 px`. Строгая шкала `16 → 26 → 42 → 68` хорошо подходит для desktop, но на маленьких экранах должна ограничиваться через `clamp()`.

| Роль | Целевой размер | Межстрочный интервал | Использование |
| --- | --- | --- | --- |
| Основной текст | 16 px | 1,55–1,65 | описания, карточки |
| Малый текст | 13 px | 1,5 | метки, вторичный текст |
| H3 | 26 px | 1,25–1,35 | названия крупных карточек |
| H2 | 42 px | 1,15–1,25 | заголовки секций |
| H1 | `clamp(42px, 5vw, 68px)` | 1,08–1,15 | главный заголовок |

`Orbitron` применять к H1/H2 и коротким акцентным числам; для длинных русскоязычных заголовков допустим текущий `Inter`, если Orbitron заметно ухудшает переносы. Основной текст и интерактивные подписи остаются `Inter`, формулы и код — `JetBrains Mono`.

## Новая композиция страницы

### Порядок секций

В [src/pages/Index.tsx](../src/pages/Index.tsx) закрепить следующую последовательность. Она переносит карту обучения раньше второстепенных аргументов и оставляет единственный финальный CTA в момент, когда пользователь уже увидел ценность.

1. `Navbar`
2. `HeroSection` — обещание, основной CTA, быстрые доказательства.
3. `DemoSection` — реальный результат обучения.
4. `ProblemSection` → `SolutionSection` — напряжение и ответ.
5. `LearningPathSection` — главный маршрут в продукт.
6. `FeaturesSection` → `UniqueValueSection` — что именно получает ученик и чем подход отличается.
7. `AudienceSection` — самосегментация посетителя.
8. `TestimonialSection` — социальное доказательство.
9. `AboutMeSection` → `OpenLearningSection` — доверие и открытые материалы.
10. `EmailCapture` — мягкий запасной CTA.
11. `FinalCTASection` — единственный завершающий призыв.
12. `FooterSection`.

Убрать визуальный хак `-mt-[2cm]`: последовательность должна задаваться отступами самих секций, а не отрицательным смещением родителя.

### Hero: главный фокус страницы

Текущий Hero полностью центрирован и содержит четыре равноправные кнопки. Его следует превратить на desktop в асимметричную композицию `61,8 % / 38,2 %`:

| Область | Доля | Содержимое |
| --- | ---: | --- |
| Левая, смысловая | 61,8 % | H1, короткое обещание, один primary CTA «Начать обучение», один secondary CTA «Посмотреть карту обучения», доверительные числа и технологические метки |
| Правая, визуальная | 38,2 % | `NeuralNetworkViz` в отдельной glassmorphism-карточке; декоративное изображение остаётся фоном, а не конкурирует с текстом |

- На ширине `lg` и выше использовать grid `1.618fr 1fr`; между колонками — `34 px`.
- Высота смысловой зоны Hero — ориентир `61,8vh`, с минимальной высотой, достаточной для контента и navbar. Не фиксировать высоту на мобильных.
- Визуальная карточка должна иметь `aspect-ratio: 1.618 / 1` или быть близка к нему. Для текущей сетевой визуализации это даёт ей понятную самостоятельную роль.
- H1 ограничить шириной большой колонки. Не разбивать текст искусственными `<br />`, если браузер способен сделать естественный перенос; оставить смысловые части в отдельных `span` только для градиентного акцента.
- Главный CTA — единственная залитая кнопка с `bg-gradient-neon`. Вторичный CTA — `outline`. Ссылки «Карта знаний», тест и кабинет переместить в компактный ряд текстовых/иконных ссылок ниже CTA или в navbar.
- Блок из четырёх чисел заменить на две большие карточки `61,8 % / 38,2 %`: например, «20 уроков и 4 проекта» и «Unity + PyTorch». Детальные цифры можно показать внутри. Это уменьшит визуальный шум над первым экраном.

### Demo: доказательство в пропорции 1,618 : 1

Для [DemoSection.tsx](../src/components/landing/DemoSection.tsx) оставить текущие видео и метрики, но заменить равные колонки на `1.618fr 1fr`.

- Видео занимает большую колонку и имеет `aspect-ratio: 1.618 / 1`.
- Правая колонка включает график награды сверху и две метрики снизу; высота всего набора выравнивается с видео.
- CTA «Перейти к проекту» выровнять по левой границе видео, а не ставить отдельной центрированной строкой: он продолжает F-траекторию чтения.
- Заголовок и краткое описание секции ограничить шириной `61,8 %` контейнера и выровнять влево на desktop; на mobile оставить центрирование.

### Карта обучения: продуктовый центр

`LearningPathSection` — главный ориентир для посетителя после первого знакомства. Ей нужна самая большая смысловая площадь на странице.

- Контейнер — до текущих `1400 px`; три этапа остаются тремя колонками, но каждая карточка получает одинаковую высоту и внутренний ритм `21 / 34 px`.
- При ширине `lg` первый этап может занимать `61,8 %` первой строки вместе с обзором пути, а этапы 2–3 — оставшуюся `38,2 %` как вертикальная пара. Применять этот вариант только если список уроков читается без прокрутки внутри карточки.
- Предпочтительный, менее рискованный вариант: оставить три равные карточки, а пропорцию использовать внутри них — верхняя область с названием и описанием `38,2 %` высоты, список уроков `61,8 %`.
- Не прятать существенный список в `overflow-y-auto` на desktop: пользователь должен видеть путь целиком или переходить на `/courses` через явный CTA.
- Легенду хабов сделать компактной отдельной зоной после карты; её внешний отступ — `55 px`, а не произвольный `mt-28`.

### Остальные секции

| Секция | Перестройка |
| --- | --- |
| `ProblemSection` / `SolutionSection` | Содержательный текст — 61,8 %, иллюстрация или схема — 38,2 %. Карточки проблем не должны выглядеть как одинаковые плитки без точки входа: первая получает большую площадь, остальные группируются справа или ниже. |
| `FeaturesSection` | Сохранить интерактивную радиальную схему, но ограничить её контейнером с отношением `1,618 : 1`. На mobile использовать существующие карточки в одном столбце или схему `1 + 2`, а не сжатый круг. |
| `AudienceSection` | Круговая схема остаётся на desktop; поместить её в квадратную визуальную область. Текстовое введение и CTA к карте обучения занимают соседнюю большую колонку. |
| `UniqueValueSection` | Сохранить интерактив, но дать поясняющей карточке 38,2 % ширины, а визуальному пути — 61,8 %. |

| `EmailCapture` / `FinalCTASection` | Содержимое ограничить `min(61,8vw, 865px)`. Поле ввода и кнопка формируют на desktop `1.618fr 1fr`; на мобильном — вертикальный стек. |

## Общие правила карточек, баннеров и изображений

1. Для крупных медиа-карточек, видео, интерактивных панелей и финального баннера использовать `aspect-ratio: 1.618 / 1`. Это правило не относится к строкам, таблицам, спискам уроков и формам.
2. Малые карточки не фиксировать в золотом прямоугольнике: их высоту определяет содержание. Вместо этого согласовать внутренние отступы через `13 / 21 / 34 px`.
3. Радиус карточки — ближайшее значение к `13 px` или `21 px`; не смешивать множество произвольных радиусов.
4. Glassmorphism сохранить через `bg-card/60 backdrop-blur-sm`. Основная карточка получает `border-primary/30`, поясняющая — `border-secondary/30`, CTA — `border-accent/30`; это создаёт семантическую иерархию без новых цветов.
5. Не использовать золотое сечение для кликабельных областей. Минимальная высота кнопок и контролов остаётся доступной: не менее `44 px`.

## Адаптивность

| Диапазон | Правило |
| --- | --- |
| `< 640 px` | Один столбец; H1 от 42 px; внешние поля 16 px; вертикальные расстояния 34–55 px; крупные медиа держат `1.618 / 1`, если это не обрезает критичный контент. |
| `640–1023 px` | Один столбец для Hero и сложных схем; две равные карточки допустимы только там, где текст не становится уже 280 px. H1 плавно растёт через `clamp()`. |
| `≥ 1024 px` | Включать макеты `1.618fr 1fr`; gap 21–34 px; контентный контейнер использует существующее ограничение `1400 px`. |

Перед реализацией проверить интерфейс на ширинах `360`, `768`, `1024`, `1440` и `1920 px`, а также при масштабе браузера `200 %`.

## Критерии готовности

- На desktop Hero и Demo явно читаются как композиции `61,8 % / 38,2 %`; CTA заметен в верхней левой области смыслового маршрута.
- Крупные визуальные панели используют отношение `1,618 : 1`, а текстовые карточки не получают искусственную фиксированную высоту.
- Типографика образует предсказуемую шкалу: основной текст `16 px`, H3 около `26 px`, H2 около `42 px`, H1 до `68 px` с адаптивным ограничением.
- На mobile нет боковых панелей, перекрытий, клиппинга интерактивов и горизонтальной прокрутки.
- Контент, навигация, ссылки на хабы, данные обучения и SEO остаются функционально неизменными.
- Цветовые классы и новые стили используют только существующие семантические токены дизайн-системы.
