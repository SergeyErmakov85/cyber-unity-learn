# Работа над cyber-unity-learn дома и в дороге

Рабочая схема: **Codex Cloud → GitHub → Lovable → опубликованный сайт**.
GitHub хранит общую версию кода, Codex Cloud выполняет задачи независимо от домашнего компьютера,
Lovable получает изменения из подключённой ветки и публикует сайт.

## Адреса

- Сайт: <https://rl-cuber-unity-code.com>
- Код: <https://github.com/SergeyErmakov85/cyber-unity-learn>
- Проверки: <https://github.com/SergeyErmakov85/cyber-unity-learn/actions>
- Локальная версия: <http://localhost:8080> на компьютере, где запущен сервер.

## Подключить Codex Cloud

1. В ChatGPT на компьютере откройте **Work in → Cloud → Select environment → Create environment**.
   Другой путь: **Settings → Codex Cloud → Environments → Create environment**.
2. Завершите вход в GitHub и предоставьте доступ к `SergeyErmakov85/cyber-unity-learn`.
   Назовите среду `cyber-unity-learn`, оставьте доступ **Only me**.
   Подключение GitHub в Lovable и доступ GitHub для Codex Cloud настраиваются отдельно.
3. Разрешите установку пакетов и доступ к GitHub, npm, загрузкам Playwright, Lovable и проекту Supabase.
   При ограничении доменов укажите фактические хосты. Для проверки внешних ссылок нужны их целевые сайты.
4. Используйте Node.js **24.x** из `.nvmrc`. В каталоге проекта выполните:

```bash
npm run setup:cloud
npx playwright install --with-deps chromium
npm run audit:browser
```

`setup:cloud` устанавливает зависимости из `package-lock.json` через `npm ci`, затем проверяет
типы, lint, ссылки, формулы и сборку. Браузерный аудит использует изолированные тестовые настройки.
Если порт 8080 занят, укажите свободный порт, например:

```bash
AUDIT_BASE_URL=http://127.0.0.1:8081 npm run audit:browser
```

5. Добавьте в **Environment variables** среды значения из домашнего `.env`
   или настроек существующего проекта Lovable:

| Имя | Значение |
|---|---|
| `VITE_SUPABASE_URL` | HTTPS-адрес проекта Supabase |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Публичный publishable key или legacy anon key |
| `VITE_SUPABASE_PROJECT_ID` | Идентификатор проекта Supabase |

Не публикуйте `.env` в GitHub. `VITE_*` попадают в браузерную сборку;
серверные ключи остаются в настройках Supabase Edge Functions.

6. Проверьте `npm run env:check`, затем запустите `npm run dev:cloud`.
   В инструкции запуска среды укажите запуск этой команды в фоне и проверку HTTP-ответа на порту 8080.
   Для просмотра на планшете используйте ссылку Lovable или опубликованный домен.
7. После успешного отчёта настройки сохраните среду и нажмите **Publish** в ChatGPT.
   Затем выберите **Start a new task**. На телефоне откройте Codex и выберите эту среду.

Кнопка Publish среды в ChatGPT сохраняет облачную рабочую среду. Публикация сайта выполняется в Lovable.
Создание среды и авторизация GitHub требуют действий в интерфейсе аккаунта;
файлы репозитория сами по себе их не выполняют.

## Проверить существующую связь GitHub и Lovable

Проект уже связан с GitHub по информации владельца. В существующем проекте Lovable проверьте:

1. **Project settings → Git → GitHub**: репозиторий `SergeyErmakov85/cyber-unity-learn`.
   Сохраните существующую связь: переподключать проект или создавать новый репозиторий не требуется.
2. Активную ветку. Для основного процесса используйте `main`.
   Lovable синхронизирует одну активную ветку; отдельная ветка PR сама по себе не получает
   самостоятельную опубликованную копию сайта.
3. После push или merge в активную ветку дождитесь появления коммита в Lovable.
   Проверьте изменённую страницу в Preview, включая прямое открытие URL урока.
4. Обновите публичный сайт через **Publish → Publish changes** и дождитесь завершения.
   В некоторых версиях интерфейса действие может называться Update.
   Git sync переносит код; успешную публикацию проверяйте отдельно.
5. Откройте основной домен на планшете и убедитесь, что нужная правка появилась.

Перед публикацией полезно выполнить `npm run build:deploy`: проверку параметров окружения
и полный набор локальных проверок. Обычные команды сборки Lovable сохраняются.
CI в GitHub запускается для `main`, `codex/**` и PR в `main`, включая браузерный аудит.
CI сообщает о результате проверки; обязательность проверки при merge задаётся в настройках GitHub.

Для входа через Supabase/OAuth используйте действующие адреса возврата и серверный `APP_URL`.
Изменять рабочие настройки авторизации для перехода к облачной разработке не требуется.

## Ежедневная работа

1. Откройте сайт на планшете. В задаче Codex Cloud на телефоне продиктуйте URL страницы,
   название раздела и нужную правку; при необходимости приложите снимок экрана.
2. Codex вносит изменение в ветке `codex/<задача>`, проверяет его и отправляет код в GitHub.
3. После проверки и объединения в `main` изменение поступает в Lovable.
4. Проверьте Preview и опубликуйте изменения в Lovable. Затем обновите страницу на планшете.

Для продолжения незавершённой работы открывайте ту же облачную задачу.
Сохраняйте важные изменения коммитами в GitHub: новая задача имеет собственную рабочую копию.
Дома также можно работать в этой облачной задаче.

## Синхронизация с домашним компьютером

Перед уходом сохраните нужные изменения коммитом и отправьте рабочую ветку в GitHub.
Укажите эту ветку в облачной задаче. Незакоммиченные локальные файлы автоматически не переносятся.

По возвращении сначала проверьте `git status` и сохраните свою незавершённую работу.
Для чистой локальной `main`:

```bash
git fetch origin
git switch main
git pull --ff-only
npm ci
npm run dev
```

Если ветки разошлись, разберите изменения без `reset --hard`.

## Справочные репозитории

Обычная сборка использует копии учебника, уже находящиеся в репозитории сайта.
Для изменения содержания учебника и проверки примеров подключите к среде также:

- <https://github.com/SergeyErmakov85/Math_for_DS_-_RL>
- <https://github.com/SergeyErmakov85/unity-ml-agents-lab>

Задайте `ENF_TEXTBOOK_SRC` равным фактическому абсолютному пути к каталогу `math-textbook`
в исходном репозитории пособия. Windows-путь не подходит для Linux-среды.
Содержание `src/content/math-textbook` правьте в исходном пособии, затем используйте
`npm run textbook:sync`. Сохраняйте изменения пособия и сайта в соответствующих репозиториях.
`npm run audit:lab` и `npm run textbook:audit` требуют доступных справочных репозиториев.
