# Публикация .md с цветной математикой на сайт

Материал приходит как `.md` с формулами и попадает на `/math-rl/textbook/...` отдельной
страницей — в цвете, со связями и без ручной вёрстки. Ниже процедура целиком; подробности
по полям, палитре и эвристике размещения — в [`reference.md`](reference.md).

## Инвариант, который нельзя нарушать

**Содержание правится только в исходном репозитории пособия.** Каталог
`src/content/math-textbook/` — копия для рендера; правка в ней разводит копии, и расхождение
всплывает не сразу. Путь к исходнику: `$env:ENF_TEXTBOOK_SRC`, по умолчанию
`C:/Math_for_DS_&_RL/math-textbook`.

Если исходник недоступен (другая машина, нет диска) — положи файл в копию, доведи задачу
до конца и **обязательно скажи пользователю**, что правку нужно перенести в исходный
репозиторий, иначе следующий `npm run textbook:sync` её сотрёт.

## Процедура

### 1. Понять, что за материал

Прочитай присланный файл целиком до любых действий. Определи:

- это **новый раздел** учебника (обычный случай) или **дополнение к существующему**;
- какой режим: `learning` (лекция, разбор, задачник) или `publication` (глава книги, статья);
- есть ли frontmatter, коллауты, диаграммы, код, ссылки наружу.

Дополнение к существующему разделу — не новый файл: вклей текст в нужное место
существующего `.md`, дальше шаги 3–8 те же.

### 2. Выбрать место

**Пользователь указал часть или тему** — используй указанное, не переспрашивай.
Формулировки вроде «в часть V», «к PPO», «в раздел про вероятность» разрешаются
по таблице частей в `reference.md`.

**Не указал** — определи сам:

1. Собери ключевые слова материала (заголовки, обозначения, термины).
2. Сопоставь с таблицей «тема → часть» из `reference.md`.
3. Проверь гипотезу по содержимому: прочитай `index.md` кандидата и заголовки соседних
   разделов — материал должен продолжать их, а не дублировать.
4. Если материал уверенно ложится в одну часть — клади и скажи в отчёте, куда и почему.
   Если кандидатов два и они равнозначны — спроси пользователя, назвав оба и разницу.

Номер файла: следующий свободный `NN-` в каталоге части. Вставка в середину требует
переименования соседних файлов и правки `order` — так делать можно, но предупреди
пользователя: старые ссылки на файлы по имени сломаются.

### 3. Привести формулы к ролевой раскраске

Цвет в ENF задаётся ролью сущности, а не оттенком. Допустимы только макросы:

| Макрос | Роль |
|---|---|
| `\enfVar{}` | переменная, объект, над которым действуем |
| `\enfFun{}` | функция, преобразование |
| `\enfPar{}` | параметр, то что настраивается и обучается |
| `\enfOp{}` | оператор, агрегат, ожидание |
| `\enfTgt{}` | целевая величина: награда, потери |
| `\enfNeu{}` | служебное, индексы, константы |

Запрещено и подлежит замене: `\textcolor{…}{…}`, `\color{…}`, `\class{…}{…}`,
инлайновые стили, юникод-математика (`∑`, `θ`) внутри формул. При замене выбирай роль
по смыслу символа, а не по прежнему цвету.

Соблюдай лимиты режима (`enf_mode`) — их проверяет `check-colors.mjs`:

- `learning` — до 4 тонов в формуле, окрашено до ~40 % символов, доступны все пять ролей;
- `publication` — до 3 тонов, до ~15 %, только `variable`, `function`, `parameter`.

Каждая окрашенная сущность должна быть объяснена словами рядом — цвет указывает
на объяснение, а не заменяет его.

### 4. Заполнить frontmatter

Обязательные поля и как считать `hub_url` / `hub_anchor_canonical` — в `reference.md`.
Генератор падает, если `part_id` не совпал с каталогом или `status` пуст.

### 5. Положить файл и пересобрать

```powershell
# файл лёг в исходный репозиторий; проверки ENF выполняются там
pwsh C:/Math_for_DS_&_RL/Scripts/check.ps1 C:/Math_for_DS_&_RL/math-textbook/<часть>/<файл>.md

# в этом репозитории
npm run textbook:sync     # копирует .md и пересобирает индекс со sitemap
```

Генератор сам добавит страницу в маршруты, оглавление части, поиск и `sitemap.xml`.

### 6. Вплести раздел

Это не делается автоматически — пройди по списку:

- **`index.md` части** (в исходном репозитории): добавить строку в список «Разделы»
  и увеличить `sections:` во frontmatter. Иначе страница есть, а в оглавлении части её нет.
- **mind map** `src/content/mathMindMap.ts`: если задан `mindmap_node`, добавить лист
  в нужную ветвь `RAW`. Подпись листа обязана совпасть с `mindmap_node` символ в символ —
  по ней ищется маршрут лекции. Маршрут руками не пишем.
- **`src/config/crosslinks.ts`**: связи с уроками курса, если материал их поддерживает.
  Каждая запись — своя формулировка контекста, не «см. также».
- **`_meta/unity-bridge.md`** (исходный репозиторий): если тема ложится на среду Unity,
  добавь строку — путь в разделе «Практика в этом репозитории» станет ссылкой на GitHub сам.

### 7. Проверить

```powershell
npm run textbook:audit    # ссылки, маршруты, карты, раскраска, мост в код
npm run audit:links       # якоря внутри сайта
npm run build
```

Затем открой страницу в браузере и убедись глазами:

- формулы **цветные**, ролей видно несколько, а не одна;
- коллауты (`> [!theorem]` и прочие) отрисованы карточками, а не цитатой;
- ссылки внутри текста ведут на страницы сайта, а не на `.md`;
- оглавление слева совпадает с заголовками.

Серые формулы почти всегда означают `\textcolor` вместо макросов — вернись к шагу 3.
Остальные симптомы — в таблице «Частые ошибки» в `reference.md`.

### 8. Отчитаться и закоммитить

В отчёте назови: куда положен материал и почему именно туда, что изменено в раскраске,
какие связи добавлены, что проверено. Коммить только по просьбе пользователя;
помни, что изменения ложатся в **два репозитория** — исходник пособия и этот.
